1 Cosa fa questo agente

Gli dici a quale database connettersi e poi gli fai domande in linguaggio normale:

  • Traduce la tua domanda in una query SELECT (sola lettura) e la esegue.
  • Ti mostra la query SQL che ha generato e il risultato.
  • Non esegue mai operazioni che modificano dati (INSERT, UPDATE, DELETE, DROP...): un validatore di sicurezza blocca qualsiasi query che non sia di lettura.
  • Funziona con SQLite, PostgreSQL e MySQL (SQLite è pronto all'uso; MySQL e PostgreSQL richiedono l'installazione della loro estensione).

Risultato: qualsiasi persona autorizzata può interrogare i dati senza dipendere dal fatto che l'IT scriva la query, e senza rischio di danneggiare nulla.

1

Scarica l'installer da tuialista.com/descargar (agente Database) e aprilo. Crea un collegamento sul desktop con il logo — non richiede Python né terminale.

2
Aprilo dal desktop e attiva la tua licenza

Doppio clic sulla nuova icona. Incolla la tua chiave di licenza (ricevuta via email all'acquisto) e premi Attiva. A differenza di altri agenti, non ti chiede di scegliere una cartella — questo agente si connette a un database, non a file locali.

3
Configura la connessione (passaggio tecnico)

Definisci le variabili d'ambiente TARGET_DB_TYPE (sqlite, postgres o mysql) e TARGET_DB_URL con i dati del tuo database. Per SQLite ti serve solo il percorso al file .db. Questo passaggio viene normalmente eseguito dal reparto IT.

3 Come usarlo

L'agente apre una finestra di chat, come un'app di messaggistica — non è uno schermo nero da programmatore. Nessun comando da memorizzare: scrivi la tua domanda in linguaggio normale nella casella di testo in basso, premi Invia (o Invio), e l'agente genera la query, la esegue e ti mostra l'SQL, le colonne e i risultati:

Se la tua domanda si traduce in qualcosa che modificherebbe dati, l'agente lo rifiuta: [Sono consentite solo query di lettura (SELECT).]

L'agente fornisce all'IA lo schema delle tue tabelle (nomi di tabelle e colonne) per costruire la query corretta. I dati vengono letti solo quando la query SELECT viene eseguita, ed è limitata a un massimo di 100 righe per risposta. Scrivi esci (o exit) per terminare.

5 Domande frequenti

Può danneggiare o cancellare i miei dati?
No. Opera in modalità sola lettura. Un validatore blocca qualsiasi query che non inizi con SELECT o che contenga operazioni di scrittura (INSERT, UPDATE, DELETE, DROP, ALTER, TRUNCATE, ecc.) o più istruzioni.
Quali database supporta?
SQLite (incluso, senza estensioni), MySQL/MariaDB e PostgreSQL (richiedono l'installazione della loro estensione). Per SQLite ti serve solo il percorso al file .db.
I miei dati vengono caricati su internet?
No. La connessione e l'esecuzione delle query avvengono sul tuo dispositivo o nella tua rete. Solo lo schema (struttura delle tabelle) e la tua domanda vengono inviati all'IA; i dati restituiti dalla query non vengono inviati al motore IA.
Ho bisogno di internet per usarlo?
Solo per convalidare la tua licenza (fino a 3 giorni offline) e perché l'IA traduca la tua domanda in SQL. La connessione al tuo database è locale.
Perché mi mostra l'SQL generato?
Per trasparenza: puoi rivedere la query prima di fidarti del risultato, e imparare come viene tradotta la tua domanda.
Quanti risultati restituisce?
Fino a 100 righe per query, come limite di sicurezza.
In quale lingua mi risponde?
Nella lingua in cui gli scrivi.
Cosa succede se l'agente genera un SQL scorretto?
Può succedere con schemi complessi o nomi ambigui. Rivedi l'SQL mostrato; se non è corretto, riformula la tua domanda essendo più specifico.
Posso cambiare database?
Sì. Cambia TARGET_DB_TYPE e TARGET_DB_URL e riavvia l'agente.
Ha bisogno di un utente speciale del database?
Si consiglia di connetterlo con un utente di sola lettura del tuo database, come livello di sicurezza aggiuntivo oltre al validatore dell'agente.

6 Risoluzione dei problemi

“Tipo di DB non supportato”
Verifica TARGET_DB_TYPE. Valori validi: sqlite, postgres (o postgresql), mysql.
Errore di connessione a MySQL o PostgreSQL
Verifica TARGET_DB_URL (host, porta, utente, password, database) e che il database accetti connessioni dal tuo dispositivo. Se hai appena cambiato motore, contatta l'assistenza — potrebbe mancare l'estensione di quel motore.
SQLite: “unable to open database file”
Il percorso in TARGET_DB_URL è errato o la cartella non esiste. Usa il percorso completo al file .db.
“Sono consentite solo query di lettura (SELECT)”
È il comportamento previsto: hai chiesto qualcosa che modificherebbe dati. L'agente fa solo query di lettura.
Mostra “Licenza non valida” o chiede di riconnettersi
Verifica che la chiave incollata sia corretta (senza spazi in più), conferma di avere internet la prima volta che attivi, e se sei stato più di 3 giorni senza connessione, riconnettiti una volta per rivalidare.
“Nessun fornitore IA configurato”
La traduzione della domanda in SQL usa IA. Se vedi questo messaggio, manca la configurazione del motore IA; contatta l'assistenza.

7 Privacy e riservatezza

Il tuo database e i suoi dati non lasciano mai la tua infrastruttura.

  • L'agente si connette al tuo database localmente (sul tuo dispositivo o nella tua rete) e vi esegue le query. I risultati non vengono caricati su nessun server.
  • Solo lo schema (nomi di tabelle e colonne) e la tua domanda vengono inviati all'IA, per redigere la query SELECT. I dati restituiti dalla query non vengono trasmessi al motore IA.
  • L'unica cosa che viaggia su internet è: (1) una verifica che la tua licenza sia attiva, e (2) lo schema + la tua domanda per generare l'SQL.
La riservatezza dei tuoi dati è garantita per progettazione, rafforzata dalla modalità sola lettura: nessun dato reale di una query arriva al fornitore di IA, solo lo schema e la tua domanda.
Promemoria importante: questo agente interroga, non decide per te. È uno strumento di sola lettura che traduce le tue domande in query SELECT. La generazione di SQL da parte dell'IA è molto utile, ma può sbagliare con schemi complessi: rivedi la query mostrata e verifica i numeri critici prima di prendere decisioni basandoti su di essi. Per la massima sicurezza, connettilo con un utente del database di sola lettura.
