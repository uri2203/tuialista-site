1 Ce que fait cet agent

Vous lui indiquez le dossier du projet et il :

  • Scanne le code et en extrait la structure (fonctions, classes, commentaires, imports).
  • Génère un README professionnel du projet (structure, composants, dépendances, usage).
  • Documente un fichier spécifique en détail (but, fonctions, paramètres, notes).
  • Génère une FAQ technique avec des questions et réponses basées sur le code.
  • Détecte les fonctions et classes non documentées.
  • Construit une carte des dépendances entre fichiers (internes et externes).
  • Répond à des questions libres sur le code.

Prend en charge de nombreux langages : Python, JavaScript/TypeScript, Java, Kotlin, C/C++, Go, PHP, Ruby, SQL, ainsi que RPG (AS/400/IBM i) et COBOL, entre autres.

2 Installation (2 minutes)

Pour Windows. Pas besoin d'internet permanent ni de rien envoyer sur le cloud.

1
Téléchargez-le et installez-le

Téléchargez l'installateur depuis tuialista.com/descargar (agent Documentation technique) et ouvrez-le. Il crée un raccourci sur votre bureau avec le logo — pas besoin de Python ni de terminal.

2
Ouvrez-le depuis le bureau

Double-cliquez sur la nouvelle icône. Collez votre clé de licence (reçue par e-mail à l'achat) et cliquez sur Activer. Une coche verte apparaît quand elle est valide.

3
Choisissez votre dossier

Sélectionnez le dossier du projet et cliquez sur Commencer à utiliser l'agent. La prochaine fois, il démarre directement — il se souvient de votre clé et de votre dossier.

3 Comment l'utiliser

L'agent ouvre une fenêtre de discussion, comme une app de messagerie — pas un écran noir de programmeur. Vous écrivez votre commande ou votre question dans le champ de texte en bas, cliquez sur Envoyer (ou Entrée), et la réponse apparaît comme un message, exactement comme sur cette image réelle :

Les commandes suivantes sont les mots que vous pouvez écrire dans ce même champ de texte :

> readme

README.md professionnel avec nom, structure, composants principaux, comment ils s'articulent, dépendances et instructions d'usage.

> faq

De 8 à 12 questions fréquentes techniques (architecture, comment quelque chose fonctionne, comment changer une fonctionnalité...) avec des réponses basées sur votre code.

> documenter <fichier>

Documentation détaillée d'un fichier : but, chaque fonction/procédure (ce qu'elle fait, paramètres, retour), dépendances et notes.

> non-documenté

Fonctions et classes sans commentaires ni docstring, avec fichier et ligne.

> dépendances

Carte des dépendances : par fichier, quels modules internes du projet et quelles bibliothèques externes il utilise.

> analyser <fichier>

Structure détectée d'un fichier (classes, fonctions avec leur ligne, imports) sans appeler l'IA.

> question libre ?

Écrivez toute question en langage naturel, ex. : où le jeton de session est-il validé ?

> quitter

Termine la session (fonctionne aussi avec exit).

5 Questions fréquentes

Mon code est-il envoyé sur internet ?
Non. Le scan et l'analyse de structure sont locaux (voir Confidentialité, section 7).
Quels langages prend-il en charge ?
Python, JavaScript/TypeScript, Java, Kotlin, Scala, C/C++, Go, PHP, Ruby, Rust, Swift, C#, VB, SQL, RPG (AS/400), COBOL, shell, PowerShell et plus, ainsi que les fichiers texte/config (Markdown, JSON, YAML, XML, HTML/CSS...).
Dois-je installer des bibliothèques supplémentaires ?
Non. Contrairement à d'autres agents, celui-ci lit les fichiers comme du texte ; il n'a besoin que des dépendances de base du SDK.
Ignore-t-il des dossiers comme node_modules ?
Oui. Il ignore node_modules, .git, __pycache__, venv, .venv, dist, build, target, .idea, .vscode, les caches, etc.
Modifie-t-il mon code ou écrit-il des fichiers ?
Non. Il génère la documentation comme texte à l'écran ; vous décidez où l'enregistrer. L'agent ne touche pas à vos fichiers.
Quelle taille peut avoir le projet ?
Il scanne tout l'arbre, mais pour générer README/FAQ/documenter il utilise un extrait du code (les fichiers et fragments les plus pertinents) pour tenir dans le contexte de l'IA.
Fonctionne-t-il pour du code AS/400 (RPG/COBOL) ?
Oui. Il extrait sous-routines, procédures et paragraphes, et la documentation utilise la terminologie IBM i quand c'est approprié.
Dans quelle langue répond-il ?
Dans la langue dans laquelle vous lui écrivez.
La documentation est-elle 100 % correcte ?
C'est un excellent point de départ généré par IA à partir de votre code ; relisez-la avant de la publier, surtout sur les détails critiques.
Puis-je documenter un seul fichier sans tout scanner ?
Au démarrage il scanne le projet une fois ; ensuite vous pouvez travailler sur des fichiers précis avec documenter et analyser.

6 Résolution de problèmes

Affiche “0 fichiers indexés”
Le dossier est vide, le chemin est incorrect ou ne contient que des types non supportés. Vérifiez que vous avez choisi le bon dossier lors de l'activation de l'agent.
Ne trouve pas un fichier avec documenter/analyser
Utilisez le chemin relatif tel qu'il apparaît dans le scan, ou juste le nom du fichier (la recherche est flexible).
Le README ignore certains fichiers
Pour tenir dans le contexte de l'IA, le README résume les composants principaux ; utilisez documenter <fichier> pour le détail d'un fichier précis.
Affiche “Licence invalide” ou demande de se reconnecter
Vérifiez que la clé collée est correcte (sans espaces en trop), assurez-vous d'avoir internet la première fois que vous activez, et si vous êtes resté plus de 3 jours sans connexion, reconnectez-vous une fois pour revalider.
“Aucun fournisseur d'IA configuré”
readme, faq, documenter et les questions libres utilisent l'IA — s'il manque la configuration du moteur, contactez le support. non-documenté, dépendances et analyser continuent de fonctionner localement, sans IA.

7 Confidentialité

Votre code source ne quitte jamais votre ordinateur.

  • L'agent scanne le projet et en extrait la structure localement, sur votre propre appareil. Il n'envoie votre code à aucun serveur.
  • La détection de structure, la dette de documentation (non-documenté) et la carte des dépendances sont calculées sur votre machine.
  • La seule chose qui transite par internet est : (1) une vérification que votre licence est active — qui n'inclut pas votre code —, et (2) lors de la génération d'un README, d'une FAQ, de la documentation d'un fichier ou d'une réponse à une question, des fragments du code (les plus pertinents) sont envoyés au moteur d'IA pour rédiger le texte.
La confidentialité de votre propriété intellectuelle est garantie par conception : non-documenté, dépendances et analyser sont 100 % locaux. Seuls readme, faq, documenter et les questions libres partagent des fragments du code avec le fournisseur d'IA.
Rappel important : la documentation générée est un excellent point de départ, pas un document final infaillible. L'agent décrit ce qu'il trouve dans le code ; il peut mal interpréter une logique très complexe ou déduire un but erroné. Relisez la documentation avant de la publier, surtout sur des projets critiques.
