1 Was dieser Agent tut

Er löst zwei teure Probleme, die aufgrund des weltweiten Mangels an IBM i-Kompetenzen schwer zu bewältigen sind:

  • Datenabfrage in DB2 for i ohne SQL- oder Systemkenntnisse. Sie stellen Fragen in normaler Sprache, und der Agent generiert eine SELECT-Abfrage in DB2 for i (schreibgeschützt), führt sie aus und zeigt Ihnen das Ergebnis.
  • Geerbten RPG- und COBOL-Code verstehen. Sie geben ihm eine RPG/COBOL-Quelldatei und er erklärt sie Ihnen in klarer Sprache: was sie tut, welche Daten sie verarbeitet und was sie produziert, ohne anzunehmen, dass Sie die Sprache kennen.

Alles geschieht lokal, innerhalb Ihres Netzwerks: die Verbindung zur IBM i und die Daten verlassen nie Ihre Infrastruktur.

Statusnotiz: Die Struktur des Agenten ist vollständig. Der End-to-End-Verbindungstest erfordert eine echte IBM i mit installiertem IBM ODBC-Treiber — diese Validierung hängt von Ihrer Umgebung ab (Systemzugang und Anmeldedaten).

2 Installation

Für Windows. Dieser Agent hat einen zusätzlichen Schritt gegenüber den anderen: die Verbindung zur IBM i wird separat konfiguriert, nicht über das Aktivierungsfenster.

1
Herunterladen und installieren

Laden Sie das Installationsprogramm von tuialista.com/descargar herunter (AS/400-Agent) und öffnen Sie es. Es erstellt eine Verknüpfung mit dem Logo auf Ihrem Desktop — kein Python oder Terminal erforderlich.

2
Öffnen Sie es vom Desktop aus und aktivieren Sie Ihre Lizenz

Doppelklicken Sie auf das neue Symbol. Fügen Sie Ihren Lizenzschlüssel ein (er wurde Ihnen beim Kauf per E-Mail zugesandt) und klicken Sie auf Aktivieren. Im Gegensatz zu anderen Agenten fragt er nicht nach einem Ordner — dieser Agent verbindet sich mit einer Datenbank, nicht mit lokalen Dateien.

3
Konfigurieren Sie die Verbindung zur IBM i (technischer Schritt)

Installieren Sie den IBM i Access ODBC Driver (von IBM i Access Client Solutions) auf dem Gerät, auf dem der Agent läuft, und definieren Sie die Umgebungsvariablen AS400_HOST, AS400_USER und AS400_PASSWORD mit den Daten Ihres Systems. Dieser Schritt wird normalerweise von der IT-Abteilung durchgeführt.

3 So verwenden Sie ihn

Der Agent öffnet ein Chat-Fenster, wie eine Messaging-App — kein schwarzer Programmierer-Bildschirm. Er hat zwei Befehle plus beenden:

> daten <Frage>

Sie schreiben Ihre Frage in natürlicher Sprache. Der Agent generiert eine SELECT-Abfrage in DB2 for i (Syntax BIBLIOTHEK.TABELLE), validiert sie als schreibgeschützt und führt sie aus. Z. B.: daten wie viele offene Bestellungen gibt es in der Bibliothek VERTRIEB? Die Ergebnisse sind auf 100 Zeilen pro Abfrage begrenzt.

> erklären <Datei>

Sie geben ihm den Pfad zu einer Datei mit RPG- oder COBOL-Quellcode, und er erklärt Ihnen ihren Zweck, die Daten, die sie verarbeitet, und was sie produziert, ohne unnötigen Fachjargon.

> beenden

Beendet die Sitzung (funktioniert auch mit exit).

Damit er gutes SQL generiert, ist es ratsam, vorher das Schema der abzufragenden Bibliothek zu laden (dies gibt der KI die Namen von Tabellen und Spalten) — dies wird von Ihrer technischen Abteilung bei der Inbetriebnahme des Agenten konfiguriert.

5 Häufig gestellte Fragen

Kann er die Produktionsdaten der IBM i ändern oder beschädigen?
Nein. Er arbeitet strikt schreibgeschützt. Der Validator blockiert jede Abfrage, die kein SELECT ist, einschließlich IBM i-eigener Befehle (CHGPF, DLTF, CLRPFM). Verbinden Sie ihn trotzdem mit einem schreibgeschützten Profil als zusätzliche Ebene.
Brauche ich den IBM-Treiber unbedingt?
Ja. Die Verbindung zu DB2 for i erfordert den IBM i Access ODBC Driver (von IBM i Access Client Solutions). Es ist eine Anforderung außerhalb von TuIAlista.
Verlassen die Daten der IBM i mein Netzwerk?
Nein. Die Verbindung und die Ausführung von Abfragen erfolgen innerhalb Ihres Netzwerks. Nur das Schema (Namen von Tabellen/Spalten) und Ihre Frage werden an die KI gesendet, um das SQL zu generieren, oder die Quelldatei, die Sie zu erklären bitten. Die von einer Abfrage zurückgegebenen Daten werden nicht an die KI-Engine gesendet.
Welche Codesprachen kann er erklären?
RPG (einschließlich ILE-RPG) und COBOL, die typischen der IBM i.
Generiert er Standard-SQL oder DB2 for i-SQL?
Von DB2 for i, mit seiner Syntax (Schemas/Bibliotheken mit Punkt, eigene Funktionen).
Wie viele Zeilen gibt eine Abfrage zurück?
Bis zu 100 Zeilen pro Abfrage, als Sicherheitslimit.
In welcher Sprache antwortet er?
In der Sprache, in der Sie ihm schreiben.
Warum ist er “Premium”?
Weil IBM i-Kompetenzen weltweit knapp sind und dieser Agent es ermöglicht, ein kritisches System abzufragen und zu verstehen, ohne dieses Spezialwissen.
Kann ich mehrere Bibliotheken ansprechen?
Ja; laden Sie das Schema der benötigten Bibliothek, bevor Sie fragen.
Ist das generierte SQL immer korrekt?
Nicht garantiert: bei komplexen Schemas kann sich die KI irren. Überprüfen Sie das angezeigte SQL und kritische Zahlen, bevor Sie darauf basierend entscheiden.

6 Problemlösung

“pyodbc und der Treiber 'IBM i Access ODBC Driver' fehlen”
Installieren Sie den ODBC-Treiber von IBM i (IBM i Access Client Solutions) auf dem Gerät, auf dem der Agent läuft. Überprüfen Sie, ob er im System registriert ist.
Verbindet sich nicht mit der IBM i
Überprüfen Sie AS400_HOST und die Netzwerkkonnektivität (Firewall/VPN). Bestätigen Sie AS400_USER/AS400_PASSWORD und dass das Profil Leserechte hat. Überprüfen Sie, ob der ODBC/DB2-for-i-Dienst auf der IBM i verfügbar ist.
“Nur Leseabfragen (SELECT) sind erlaubt”
Das ist das erwartete Verhalten: Sie haben etwas angefragt, das Daten ändern würde. Der Agent fragt nur ab.
Zeigt “Lizenz ungültig” oder fordert erneute Verbindung
Überprüfen Sie, ob der eingefügte Schlüssel korrekt ist (ohne zusätzliche Leerzeichen), stellen Sie sicher, dass Sie beim ersten Aktivieren Internet haben, und wenn Sie mehr als 3 Tage offline waren, verbinden Sie sich einmal erneut zur Neuvalidierung.
“Keine KI-Anbieter konfiguriert”
Sowohl daten als auch erklären verwenden KI. Sehen Sie diese Meldung, fehlt die Konfiguration der KI-Engine; kontaktieren Sie den Support.

7 Datenschutz und Vertraulichkeit

Ihre IBM i, ihre Daten und Ihr Code verlassen nie Ihr Netzwerk.

  • Der Agent verbindet sich lokal mit der IBM i (innerhalb Ihres Netzwerks) und führt die Abfragen dort aus. Die Ergebnisse werden auf keinen Server hochgeladen.
  • Nur das Schema (Namen von Tabellen/Spalten) und Ihre Frage werden an die KI gesendet, um die SELECT-Abfrage zu verfassen, oder die RPG/COBOL-Quelldatei, die Sie zu erklären bitten. Die von einer Abfrage zurückgegebenen Daten werden nicht an die KI-Engine übertragen.
  • Das Einzige, was über das Internet läuft, ist: (1) eine Überprüfung, dass Ihre Lizenz aktiv ist, und (2) der notwendige Kontext (Schema + Frage, oder der zu erklärende Code), um die Antwort zu generieren.
Die Vertraulichkeit Ihres geerbten Systems ist durch Design garantiert, verstärkt durch den schreibgeschützten Modus: keine echten Daten einer Abfrage erreichen den KI-Anbieter, nur das Schema und Ihre Frage.
Wichtiger Hinweis: Sie arbeiten auf einem kritischen System. Gehen Sie vorsichtig vor. Der Agent ist schreibgeschützt und validiert jede Abfrage, aber die SQL-Generierung durch KI kann sich bei komplexen Schemas irren, und die Code-Erklärungen sind indikativ. Überprüfen Sie das angezeigte SQL, verwenden Sie ein schreibgeschütztes IBM i-Profil und überprüfen Sie das Kritische, bevor Sie Entscheidungen treffen.
