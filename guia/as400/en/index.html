2 Installation

For Windows. This agent has one extra step compared to the others: the connection to the IBM i is configured separately, not from the activation window.

1
Download and install it

Download the installer from tuialista.com/descargar (AS/400 agent) and open it. It creates a desktop shortcut with the logo — no Python or terminal needed.

2
Open it from your desktop and activate your license

Double-click the new icon. Paste your license key (you received it by email when you bought it) and click Activate. Unlike other agents, it won't ask you to choose a folder — this agent connects to a database, not to local files.

3
Configure the IBM i connection (technical step)

Install the IBM i Access ODBC Driver (from IBM i Access Client Solutions) on the machine running the agent, and set the environment variables AS400_HOST, AS400_USER and AS400_PASSWORD with your system's details. This step is usually done by the IT team.

3 How to use it

The agent opens a chat window, like a messaging app — not a programmer's black screen. It has two commands plus exit:

> data <question>

Type your question in natural language. The agent generates a SELECT query for DB2 for i (LIBRARY.TABLE syntax), validates it as read-only, and runs it. E.g.: data how many open orders are there in the SALES library? Results are capped at 100 rows per query.

> explain <file>

You give it the path to an RPG or COBOL source file and it explains its purpose, the data it handles, and what it produces, without unnecessary jargon.

> exit

Ends the session (exit also works).

For it to generate good SQL, it's worth loading the schema of the library you'll be querying beforehand (it gives the AI table and column names) — your technical team sets this up when getting the agent running.

5 Frequently asked questions

Can it modify or damage the IBM i's production data?
No. It operates in strictly read-only mode. The validator blocks any query that isn't a SELECT, including IBM i-specific commands (CHGPF, DLTF, CLRPFM). Still, connect it with a read-only profile as an extra layer.
Do I absolutely need the IBM driver?
Yes. Connecting to DB2 for i requires the IBM i Access ODBC Driver (from IBM i Access Client Solutions). It's a requirement external to TuIAlista.
Does the IBM i's data leave my network?
No. The connection and query execution happen inside your network. Only the schema (table/column names) and your question are sent to the AI to generate the SQL, or the source file you ask it to explain. The data a query returns is never sent to the AI engine.
What code languages can it explain?
RPG (including ILE-RPG) and COBOL, the typical IBM i languages.
Does it generate standard SQL or DB2 for i SQL?
DB2 for i, with its own syntax (dot-notation schemas/libraries, its own functions).
How many rows does a query return?
Up to 100 rows per query, as a safety limit.
What language does it reply in?
Whatever language you write to it in.
Why is it “Premium”?
Because IBM i talent is scarce worldwide, and this agent lets you query and understand a critical system without that specialized knowledge.
Can I point it at several libraries?
Yes; you load the schema for the library you need before asking a question.
Is the generated SQL always correct?
Not guaranteed: on complex schemas the AI can make mistakes. Review the SQL shown and verify critical figures before deciding based on them.

6 Troubleshooting

“Missing pyodbc and the 'IBM i Access ODBC Driver'”
Install the IBM i ODBC driver (IBM i Access Client Solutions) on the machine running the agent. Verify it's registered in the system.
It won't connect to the IBM i
Check AS400_HOST and network connectivity (firewall/VPN). Confirm AS400_USER/AS400_PASSWORD and that the profile has read permissions. Check that the ODBC/DB2 for i service is available on the IBM i.
“Only read queries (SELECT) are allowed”
This is expected behavior: you asked for something that would modify data. The agent only queries.
It says “Invalid license” or asks to reconnect
Check that the key you pasted is correct (no extra spaces), make sure you have internet the first time you activate, and if you've been offline for more than 3 days, reconnect once to revalidate.
“No AI providers configured”
Both data and explain use AI. If you see this message, the AI engine isn't configured; contact support.

7 Privacy and confidentiality

Your IBM i, its data and your code never leave your network.

  • The agent connects to the IBM i locally (inside your network) and runs queries there. Results aren't uploaded to any server.
  • Only the schema (table/column names) and your question are sent to the AI to draft the SELECT query, or the RPG/COBOL source you ask it to explain. The data a query returns is never transmitted to the AI engine.
  • The only thing that travels over the internet is: (1) a check that your license is active, and (2) the necessary context (schema + question, or the code to explain) to generate the reply.
The confidentiality of your legacy system is guaranteed by design, reinforced by read-only mode: no real query data ever reaches the AI provider, only the schema and your question.
